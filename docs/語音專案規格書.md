# 語音專案規格書（voice-studio-project v1）

這份規格書給**以後設計程式（遊戲、教材、互動網頁）的人或 AI** 使用。
只要照這份規格產生一個「語音專案檔」（`.voiceproj.json`），就能匯入手機的「語音工作室」App，
在手機上離線產生全部語音，再把產出的檔案放回程式裡播放。

> 給 AI 的一句話：**「請依照 RFPSCode/voice-studio-app 的 docs/語音專案規格書.md，為這個程式產生語音專案檔 `<id>.voiceproj.json`，並讓程式用 game-voice-v1 格式（voice/all.txt + voice/map.txt）播放語音。」**

---

## 1. 整體流程

```
程式（電腦）                                   手機 App「語音工作室」
────────────────                              ─────────────────────────
① 程式產生 <id>.voiceproj.json   ──傳到手機──▶  ② 匯入專案
   （台詞、角色、音色、情緒指令）                 ③ 離線產生語音（Qwen3-TTS）
                                                  試聽、重錄、選版本、兒童音色後製
⑤ 程式讀 voice/all.txt + map.txt ◀──匯出──────  ④ 匯出 all.txt + map.txt
   依 key 播放每一句、對嘴型
```

- 傳到手機的方法：LINE／Google 雲端硬碟／USB／Email 都可以；或把檔案放在網路上，App 用「從網址匯入」（例如 GitHub 的 raw 連結）。
- 同一個專案（`id` 相同）再次匯入時，App 只會把**內容改過的句子**標成「需要重錄」，其他句子保留。

---

## 2. 檔案格式

- 編碼 UTF-8 的 JSON，副檔名 `.voiceproj.json`（App 也接受 `.json`）。
- 大小建議 2 MB 以內；句子數建議 2000 句以內。
- 未列在規格中的欄位會被保留但忽略，可以用來放程式自己的資料（建議以 `x_` 開頭）。

### 2.1 最上層欄位

| 欄位 | 必填 | 型別 | 說明 |
|---|---|---|---|
| `format` | ✔ | 字串 | 固定 `"voice-studio-project"` |
| `version` | ✔ | 整數 | 固定 `1` |
| `id` | ✔ | 字串 | 專案代號，小寫英數與 `-`，2–64 字，例如 `campus-safety-time-machine`。**同一個程式永遠用同一個 id**，App 才能沿用已錄好的句子 |
| `title` | ✔ | 字串 | 顯示名稱，例如「校園安全時光機」 |
| `description` |  | 字串 | 說明 |
| `updated` |  | 字串 | 產生時間（ISO 8601） |
| `engine` |  | 物件 | 見 2.2 |
| `instruct` |  | 字串 | **全部句子共用**的說話指令，例如「用台灣口音的國語說話，咬字清楚自然」 |
| `pronunciation` |  | 陣列 | 發音修正，見 2.5 |
| `roles` | ✔ | 陣列 | 角色，見 2.3 |
| `lines` | ✔ | 陣列 | 台詞，見 2.4（陣列順序＝輸出音檔裡的順序） |
| `output` |  | 物件 | 輸出設定，見 2.6 |

### 2.2 `engine`

| 欄位 | 預設 | 說明 |
|---|---|---|
| `model` | `"qwen3-tts-customvoice"` | 目前只有這個（Qwen3-TTS 12Hz 1.7B CustomVoice）。App 讓使用者選「標準 Q8_0」或「快速 Q4_K_M」量化版本 |
| `language` | `"chinese"` | 小寫語言名稱：`chinese` `english` `japanese` `korean` `german` `french` `russian` `portuguese` `spanish` `italian` `auto` |
| `temperature` | `0.8` | 0–1.5，越高越有變化（也越容易出錯） |
| `topP` | 模型預設 | 0–1 |
| `seed` | `-1` | `-1`＝每次隨機；固定數字可以重現同樣的結果 |

### 2.3 `roles[]` 角色

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | ✔ | 角色代號（英數、`_`、`-`），台詞用它指定角色，也會出現在 `key` 裡 |
| `name` | ✔ | 顯示名稱，例如「小凱(五年級)」 |
| `speaker` | ✔ | 內建音色，見下表 |
| `instruct` |  | 這個角色**固定的**說話方式（年齡感、個性、音色），例如「小學五年級男生，愛玩、說話大聲」。不要寫情緒（情緒寫在每一句） |
| `post` |  | 兒童音色後製，見 2.3.1 |

**內建音色（`speaker`）**

| 音色 | 特色 | 適合 |
|---|---|---|
| `vivian` | 明亮、帶點個性的年輕女聲（中文） | 女學生、小女孩（配合後製） |
| `serena` | 溫暖、溫柔的年輕女聲（中文） | 老師、媽媽、天使、旁白 |
| `uncle_fu` | 成熟、低沉圓潤的男聲（中文） | 旁白、爸爸、校長、長輩 |
| `aiden` | 陽光、清楚的年輕男聲（英文母語） | 男學生、小男孩（配合後製） |
| `ryan` | 有活力、節奏感強的男聲（英文母語） | 反派、運動員 |
| `dylan` | 年輕男聲，**會自動帶北京腔** | 一般不建議（台灣口音不合） |
| `eric` | 活潑男聲，**會自動帶四川腔** | 一般不建議 |
| `ono_anna` | 俏皮的日文女聲 | 日文內容 |
| `sohee` | 溫暖的韓文女聲 | 韓文內容 |

- 模型沒有兒童音色：兒童角色請用 `vivian`／`aiden`，在 `instruct` 寫年齡，再開 `post` 後製。
- 只有 9 個音色，角色可以共用同一個音色，用不同的 `instruct` 和 `post` 參數區分。

#### 2.3.1 `post` 兒童音色後製（在手機上做，不影響模型）

| 欄位 | 預設 | 範圍 | 說明 |
|---|---|---|---|
| `enabled` | `false` | | 是否後製 |
| `pitchHz` | `0` | 0, 150–500 | 這個角色**平均**音高的目標值（Hz），`0`＝不改音高。每一句的高低起伏會保留 |
| `formant` | `1.0` | 0.8–1.4 | 共振峰倍率（聲道長短）。1.15–1.25 最像小孩；只調音高不調共振峰會像卡通鼠聲 |
| `speed` | `1.0` | 0.7–1.3 | 語速倍率 |

建議值：

| 年齡 | `pitchHz` | `formant` |
|---|---|---|
| 8 歲男孩 | 290 | 1.20 |
| 8 歲女孩 | 310 | 1.22 |
| 11 歲男孩 | 240 | 1.14 |
| 11 歲女孩 | 265 | 1.14 |
| 天使／小精靈 | 300 | 1.10 |
| 大人 | 不後製 | |

### 2.4 `lines[]` 台詞

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | ✔ | 句子代號（英數、`_`、`-`），專案內不可重複，**改台詞時不要改 id**。建議 `001`、`case2-07` 這種格式 |
| `role` | ✔ | 角色 `id` |
| `text` | ✔ | 畫面上顯示的台詞（也是預設要唸的文字） |
| `say` |  | 實際要唸的文字（和 `text` 不同時才填）。用在：數字改中文（`20.1萬`→`二十點一萬`）、多音字改同音字、刪掉括號註解 |
| `instruct` |  | 這一句的情緒／語氣，用簡短中文，例如「痛得哭出來，聲音發抖」「壓低聲音，狡猾地慫恿」 |
| `key` |  | 程式播放時用的查詢鍵。不填時依 `output.keyFormat` 產生（預設 `{role}\|{text}`） |
| `note` |  | 備註（App 會顯示，不影響語音） |

**每一句真正送進模型的內容：**
- 文字＝`say`（沒有就用 `text`），再套用 `pronunciation`
- 指令＝`instruct`（全域）＋ `roles[].instruct` ＋ `lines[].instruct`，以「；」相接
- 音色＝`roles[].speaker`

**寫台詞與指令的建議**
- 一句不要超過 80 個字；太長請拆成兩句（兩個 id）。
- 不要放 `<laugh>` `[笑]` 這類標記，模型會照唸。笑、嘆氣、倒抽一口氣請寫在 `instruct`（例如「一開始帶著笑聲」）。
- 不要用「嘿嘿、嘻嘻、哈哈」這類語氣詞來表達情緒，唸起來很假；寫在 `instruct`。
- 數字、英文縮寫、符號請在 `say` 寫成要唸的樣子：`119`→`一一九`、`3:00`→`三點`、`km`→`公里`。
- 指令用短句、具體描述聲音：「很害怕，聲音發抖」比「害怕」好；同一種情緒盡量用同一句話描述，聲音會比較一致。

### 2.5 `pronunciation[]` 發音修正

```json
"pronunciation": [
  { "from": "縫了好幾針", "to": "逢了好幾針" },
  { "from": "一行人", "to": "一航人" }
]
```
- 依陣列順序，在每一句要唸的文字裡把 `from` 換成 `to`（同音字），只影響語音，不影響畫面。
- 修改這個表後重新匯入，用到的句子會自動標成「需要重錄」。

### 2.6 `output` 輸出設定

| 欄位 | 預設 | 說明 |
|---|---|---|
| `type` | `"game-voice-v1"` | 輸出格式，見第 3 節 |
| `sampleRate` | `24000` | 固定 24000 |
| `mp3Kbps` | `64` | MP3 位元率（32–160） |
| `leadSec` | `0.5` | 音檔開頭的空白秒數 |
| `gapSec` | `0.4` | 句子之間的空白秒數 |
| `keyFormat` | `"{role}\|{text}"` | `key` 的預設格式，可用 `{role}` `{text}` `{id}` |

## 3. 輸出格式 game-voice-v1（程式要讀的檔案）

App 匯出兩個檔案（存在手機的 `Download/語音工作室/<專案id>/`，也可以直接分享）：

| 檔案 | 內容 |
|---|---|
| `all.txt` | 全部句子接成**一個 MP3**（24 kHz 單聲道），再轉成 **base64 文字**（GitHub Pages、各種主機都能放） |
| `map.txt` | JSON：`{ "<key>": [開始秒數, 長度秒數, "嘴型數字串"], ... }` |

- 嘴型數字串：每 40 ms 一個數字（25 fps），`0`＝閉嘴、`9`＝張最大。
- 只會包含已經錄好的句子；沒錄的句子不會出現在 `map.txt`，程式要自己改用裝置朗讀或略過。
- 檔案放在程式的 `voice/` 資料夾：`voice/all.txt`、`voice/map.txt`。

### 3.1 程式播放範例（瀏覽器）

```js
const VO = { map: {}, el: null };
async function loadVoice() {
  VO.map = JSON.parse(await (await fetch('voice/map.txt')).text());
  const b64 = (await (await fetch('voice/all.txt')).text()).trim();
  const bin = atob(b64), u = new Uint8Array(bin.length);
  for (let i = 0; i < bin.length; i++) u[i] = bin.charCodeAt(i);
  VO.el = new Audio(URL.createObjectURL(new Blob([u], { type: 'audio/mpeg' })));
}
// key 例如 'xiaokai|快點過來！我們要去操場搶籃球場！'
function playLine(key, onMouth) {
  const m = VO.map[key]; if (!m) return false;            // 沒有語音 → 改用 speechSynthesis
  const [start, dur, lips] = m, el = VO.el;
  el.currentTime = Math.max(0, start - 0.04); el.play();
  const tick = () => {
    const t = el.currentTime - start;
    if (t >= dur || el.paused) { el.pause(); onMouth && onMouth(0); return; }
    const i = Math.floor(t * 25); onMouth && onMouth(i >= 0 && i < lips.length ? +lips[i] / 9 : 0);
    requestAnimationFrame(tick);
  };
  requestAnimationFrame(tick); return true;
}
```

- 手機瀏覽器第一次播放前需要使用者點擊（解鎖音訊）。
- 建議程式也提供「匯入語音」按鈕：讓使用者在手機上直接選 `all.txt` 和 `map.txt`，存在 IndexedDB，不用重新上傳網站（`校園安全時光機` 的 `index.html` 有完整範例：`VDB`、`importVoiceFiles`、`loadVoice`）。

```json
  "version": 1,

  "title": "防災小勇士",
  "engine": { "model": "qwen3-tts-customvoice", "language": "chinese", "temperature": 0.8 },

  "pronunciation": [],

    { "id": "kid", "name": "小安(三年級)", "speaker": "aiden", "instruct": "小學三年級男生，聲音稚嫩",
      "post": { "enabled": true, "pitchHz": 280, "formant": 1.18, "speed": 1.0 } }
  ],
  "lines": [
    { "id": "001", "role": "nar", "text": "地震來了！要先做什麼呢？", "instruct": "緊張、語速稍快" },
    { "id": "002", "role": "kid", "text": "趴下、掩護、穩住！", "instruct": "堅定有力地大聲說" },
    { "id": "003", "role": "nar", "text": "答對了！請撥119。", "say": "答對了！請撥一一九。", "instruct": "開心地稱讚" }

```

## 5. 驗證清單（產生專案檔的程式請自行檢查）

1. `format`、`version`、`id`、`title`、`roles`、`lines` 都存在；`id` 符合 `^[a-z0-9][a-z0-9-]{1,63}$`。
2. 角色 `id` 不重複；每個 `speaker` 在 9 個音色內。
3. 句子 `id` 不重複；每句的 `role` 都找得到角色。
4. `text` 不是空的、不超過 300 字；`say`／`text` 裡沒有 `<…>` 或 `[…]` 標記。
5. 產生的 `key` 不重複（重複的台詞請用不同的 `key`，或保證兩句內容完全相同時只需錄一次）。
6. `post` 數值在範圍內。

可以用 `docs/voiceproj.schema.json`（JSON Schema 2020-12）做格式驗證，或用 `pc/語音專案編輯器.html` 開啟檔案，它會列出所有錯誤。

## 6. 版本與相容性

- 本規格 `version: 1`。之後新增欄位會保持向下相容；不相容的修改會把 `version` 改成 2，App 會同時支援舊版。
- 模型：Qwen3-TTS-12Hz-1.7B-CustomVoice（Apache 2.0，可商用），GGUF 轉換與推論引擎 qwentts.cpp（MIT）。
- 輸出 MP3 由 shine 編碼器產生（LGPL）。
